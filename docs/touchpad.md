# 安卓触控板功能设计

> 状态：**主体已实现**（macOS/Windows 双平台注入、手势、数字键盘、引导页）；震动调教/占用状态/pong 延迟为 TODO。本文是「安卓触控板」功能的设计来源；总纲见 [ARCHITECTURE.md](ARCHITECTURE.md)。
> 依赖：局域网星型群（[ws-design.md](ws-design.md)）、Android 前台 MotionEvent 采集、桌面端系统级输入注入。

## 1. 定位与已确认决策

把安卓手机当作 PC 的触控板：手机全屏采集触摸，增量事件经**专用 UDP 通道**直送桌面端，注入为系统光标/滚动/点击（Windows `SendInput`、macOS `CGEvent`）。目标是**低延迟、纯黑省电、手势直观、反馈可感**。

已拍板（不可随意推翻）：

| 维度 | 决策 |
|---|---|
| 传输通道 | **独立专用 UDP**（不与群组 ws 混用；实际实现为 UDP 45700，原设计 TCP）；ws 只负责发现/连接信息交换 |
| 拓扑 | 手机 = 控制端，PC = 被控端；**点对点直连**，不经群主转发 |
| 坐标语义 | 传**增量 dx/dy**而非绝对坐标；PC 端光标位置由系统维护 |
| 屏幕背景 | 触控板页面背景由**设置项「OLED 模式」**控制：开=纯黑 `#000000`（不发光像素、最省电）；关=深灰（默认建议 `#212121`，护眼/降低对比）。进入触控板页时按当前设置取背景 |
| 数字键盘 | 半屏浮层，手势开/关、手势切左右；**不抢占触控板手势**（见 §4） |
| 震动 | 接入系统震动反馈，强度/开关可调（见 §5） |
| 粒子特效 | **可选增强**，默认可关，性能优先（见 §6） |
| 生命周期 | 触控板页面仅**前台**工作；离开页面即断开 UDP、停止采集与注入 |
| 独占控制 | **一对一**：一台桌面设备同一时刻只能被一台安卓设备控制，一台安卓设备同一时刻只能控制一台桌面设备（详见 §11.3） |
| UI 范围 | **本期只做安卓端 UI**（第 4 个 tab「触摸板」）；桌面端本期**不做 UI 相关逻辑**，仅保留数据面注入能力 |
| 粒子实现 | 允许使用**第三方依赖**实现粒子特效（手动实现代价高）；仍保持可开关、性能优先（见 §6） |

## 2. 整体数据流

```
┌─ Android（控制端）────────────────────────────────┐
│ TouchpadScreen（纯黑全屏）                        │
│   ├─ MotionEvent 采集 → 手势识别 → 增量打包         │
│   ├─ 数字键盘浮层（半屏，左/右）                    │
│   ├─ 震动反馈（按事件触发）                         │
│   └─ 粒子特效（可选，触碰点渲染）                    │
│         │ 专用 UDP（JSON 帧，见 §3）               │
└─────────┼──────────────────────────────────────────┘
          ▼
┌─ Desktop（被控端，Tauri）──────────────────────────┐
│   UDP 监听 → 解帧 → 事件分发                       │
│     → Windows SendInput / macOS CGEvent 注入        │
└─────────────────────────────────────────────────────┘
```

- **连接建立**：复用局域网发现拿到的 PC `addr`；手机连 PC 的触控板 UDP 端口（45700）。连接参数由群组/发现层提供，但**数据面独立于 ws**。
- **前台约束**：Android 前台 Activity 才能采集 MotionEvent；App 退后台立即断开，避免"手关机了光标还在动"。
- **幂等/乱序**：增量事件是流式，允许极端丢帧（下一段 dx/dy 承接当前位置），但**按键 down/up 必须成对可靠送达**（见 §3 可靠性）。

## 3. 事件协议（专用 UDP）

### 3.1 帧格式

优先**紧凑二进制帧**（1 字节类型 + 载荷）把延迟和包体压到最低；首版可用 JSON 降级实现，字段对齐如下。所有事件带 `seq`（单调递增，接收端用于丢弃乱序旧帧）。

| 事件 | type | 载荷 | 说明 |
|---|---|---|---|
| 握手 | `hello` | `{token, device_id, screen_w, screen_h}` | 连接后首帧；token 校验防误连 |
| 移动 | `move` | `{seq, dx, dy}` | 相对位移，浮点或定点整数；高频 |
| 滚动 | `scroll` | `{seq, dx, dy}` | 双指滚动增量（与移动分离） |
| 按键按下 | `down` | `{seq, button}` | button: left/right/middle |
| 按键抬起 | `up` | `{seq, button}` | 与 down 成对 |
| 点击 | `click` | `{seq, button}` | 点按（down+up 合成，PC 端一次注入） |
| 双击 | `dblclick` | `{seq, button}` | 双击拖拽起手 |
| 拖拽 | `drag` | `{seq, btn, phase}` | phase: start/move/end |
| 按键输入 | `key` | `{seq, code}` | 数字键盘的按键（见 §4.3） |
| 心跳 | `ping` | `{ts_ms}` | 保活（延迟测量/pong 为 TODO，当前只发 ping 无应答） |

### 3.2 可靠性

- **move/scroll**：允许丢帧（不重传旧帧，接收端按 seq 丢弃过期包），保证光标跟手、不积压。
- **down/up/key**：可靠送达（不经丢弃逻辑），且 PC 端做**松开兜底**：连接断开或超时未收到 up 时，注入一次全局抬起，防止"按键卡住"。
- **背压**：发送队列超过阈值（如 64 帧）丢弃最旧的 move/scroll，只保留最新位置增量。

## 4. 数字键盘（显示/隐藏 + 左右切换）

### 4.1 形态

- 触控板页面上方覆盖一个**半屏浮层**（占屏幕高度的 1/2 或宽度的一半，见 4.2），承载数字键盘：0-9、小数点、退格（加减乘除/回车已废弃）。
- 浮层背景保持**纯黑**，按键为深色描边 + 主色高亮（与全局主题一致），不破坏 OLED 省电目标。
- 键盘按键点击 → 发 `key` 事件注入 PC；按键触发点按震动（见 §5）。

### 4.2 手势定义（关键：不与触控板手势冲突）

约定一条**统一的唤出/切换手势**，并明确它与普通触控操作的边界：

| 手势 | 动作 | 效果 |
|---|---|---|
| 唤出/隐藏数字键盘 | 双击右下角**快捷方块**（⌘） | 显示/隐藏数字键盘（底部上滑唤出/下滑隐藏已废弃） |
| 切换位置 | 在数字键盘浮层上**左右横滑** | 浮层在**左半屏 ⇄ 右半屏**间切换 |

说明：
- 数字键盘显示时，**触控板采集区收窄为浮层以外的半屏**——此时单指移动/双指滚动仍可用，但作用于剩余半屏，手感一致。
- 横滑切位置按位移阈值判定。
- 三指手势（三指轻点开关、三指左右滑换边）已废弃，代码中未实现。

### 4.3 键盘输入语义

- 数字键盘的每次按键 → `key{code}` 事件 → PC 端注入对应键码（0-9: `VK_0`~`VK_9` / `CGKeyCode`，符号类似）。
- 输入目标是 PC 当前焦点窗口（与触控板注入目标一致），不做手机端文本框。
- 位置状态（左/右）与显示状态（显示/隐藏）都是**本地 UI 状态**，不跨设备同步、不持久化（退出触控板页重置为隐藏）。

## 5. 震动反馈（"震动调教"，TODO）

> 当前仅实现单一短促震动（`Haptics.tick()`）用于长按拖拽/按键；下述分级/档位/开关均为 TODO。

接入 Android `Vibrator`（`VibratorManager` API 31+，兼容 `Vibrator`）做事件驱动反馈，并提供**可调设置**：

| 事件 | 震动 | 说明 |
|---|---|---|
| 点按 `click` | 短促轻震（如 15ms） | 确认落点 |
| 双击/拖拽起手 | 双震或略强（如 20ms×2） | 区分单击 |
| 数字键盘按键 | 极短轻震（如 10ms） | 打字感 |
| 唤出/切换键盘 | 中等一震（如 30ms） | 手势确认 |
| 连接/断连 | 特定节奏（连接短两下、断连长一下） | 状态提示 |

可调项（"调教"）：
- **总开关**：默认开；用户可全局关闭。
- **强度档位**：轻/中/强（映射到 duration 或 amplitude），设置页/触控板页内可切换。
- **逐事件开关**（可选）：允许单独关闭"移动震动"等高频反馈，避免连续震动手麻。
- 震动仅在**前台触控板页**触发；退后台不震。
- 无震动硬件的设备静默降级（检测 `hasVibrator()`），不影响功能。

## 6. 粒子特效
### 6.1 粒子风格（关闭 / 涟漪 / 烟花）

触摸粒子特效为三态设置（`particle_style`，默认关闭）：

| 风格 | 效果 | 开放设置 |
|---|---|---|
| 关闭 | 无粒子 | — |
| 涟漪 | 触点沿圆周匀速扩散的涟漪粒子，可带拖尾 | 颜色 / 大小 / 数量 / 扩散速度 / 拖尾 |
| 烟花 | 从屏幕底部发射火箭升空到触点绽放，火箭与爆炸粒子均带烟雾尾迹，爆炸粒子受重力下沉 | 颜色 / 扩散速度（随机色=每枚烟花一个固定随机色） |

烟花引擎 `FireworkSystem.kt`（纯 Kotlin 对象池）与涟漪引擎 `ParticleSystem.kt` 平行；
渲染层 `FireworkCanvas.kt` / `ParticleCanvas.kt` 均用 `withFrameNanos` 跟随设备刷新率。
（可选增强）

触碰时在触点渲染短暂粒子/涟漪，提升反馈感。**明确为可选、性能优先**：

- **开关**：默认**关**（保证低端机与省电）；设置里可开。
- **实现**：**允许引入第三方依赖**实现（如粒子系统库）——手动维护粒子生命周期/插值/回收代价高；若用依赖，选型时告知用户确认。**要求不变**：可开关、性能降级、渲染与采集解耦。
- **OLED 友好**：粒子用**亮色小点**（白/主色）绘制在深色底（OLED 模式下为纯黑）上——仅点亮局部像素；不用大面积渐变。
- **降级**：帧率低于阈值或开关关闭时不渲染；粒子特效**不影响事件采集与注入**（渲染与采集解耦，掉帧只丢视觉，不丢控制）。
- 与数字键盘共存：浮层区域内也可渲染，但按键高亮优先。

## 7. 桌面端注入

- **Windows**（已完成）：`SendInput` 注入相对移动（`MOUSEEVENTF_MOVE`）、滚轮（`MOUSEEVENTF_WHEEL`）、按键（`MOUSEEVENTF_LEFTDOWN/UP` 等）、键码（`keybd_event`/SendInput KEYBD）。
- **macOS**（已完成）：`CGEvent` 对应 `CGEventCreateMouseEvent`（move/leftDown/leftUp/otherMouse）、`CGEventCreateScrollWheelEvent`、`CGEventCreateKeyboardEvent`。
- **权限**：macOS 需辅助功能/输入监控授权（首次引导）；Windows 一般免授权。
- 注入在**独立线程**执行，与 Tauri 主 UI 解耦；接收循环按 `seq` 过滤 + 松开兜底（见 §3.2）。

## 10. 风险与待定

- **延迟**：UDP + JSON + 高频事件丢弃 + 直连保障；pong 延迟测量为 TODO（当前只发 ping 不测 RTT）。
- **手势冲突**：底部唤出手势与"从底部开始的移动/拖拽"冲突——靠限定底部安全区 + 阈值判定；实机调参。
- **系统注入权限**：macOS 辅助功能授权是硬性前置，需在引导页说明；无授权时功能不可用并给出提示。
- **震动舒适度**（TODO）：强度档位与逐事件开关未实现，当前仅单一短震。
- **粒子性能**：低端机 Canvas 粒子掉帧——默认关、上限粒子数、渲染与采集解耦。
- **touchpad 入口**：已定——安卓群页新增第 4 个 tab「触摸板」（见 §11）；桌面端本期不做 UI。
- **多 PC / 多手机**：首版一对一（见 §11.3）；一对多连接选路由后续扩展。

## 11. 安卓端 UI 设计（本期范围）

> 本节是**本期要做的 UI**；桌面端本期**不做任何 UI 相关逻辑**，仅保留数据面注入能力。

### 11.1 入口与布局

- 在安卓群页面板新增**第 4 个 tab「触摸板」**，与现有的「群信息 / 剪切板 / 文件」并列（改 `GroupTabs.kt` 的 tab 列表 + pager）。
- tab 内容分**两块列表**，布局**参照群信息 tab（`GroupTabs.kt::DevicesTab`）**：
  - 外层 `Column`，上部 `Column(Modifier.weight(1f).verticalScroll(rememberScrollState()))` 承载两块内容，同容器一起滚动。
  - 每块 = 标题（`14.sp SemiBold`，如群信息 tab 的「群信息」「设备列表」）+ 内容卡片（`surface` 背景、`RoundedCornerShape(12dp)`）。
- 两块内容顺序：
  1. **设备列表**（可连接的桌面设备）
  2. **触摸板设置列表**（三个开关，见 11.4）

### 11.2 设备列表

- 数据源：当前群成员表 `AppState.session.value.members`，筛出 `platform ∈ {windows, macos}` 的桌面设备（复用 `DeviceInfo.platform` 字段，群成员表已带）。
- 每行展示：设备名 + 平台图标（`ic_os_win` / `ic_os_mac`，现有 drawable）+ 连接状态角标（如"控制中"/"被占用"）。
- **点击设备** → 弹出**二次确认弹窗**（复用统一组件 `KnotConfirm`，与退出群/删除文件同款）：
  - 标题：`连接触摸板`（或直接用设备名）
  - 文案：**"即将作为此设备的触摸板"** + 设备名（i18n key `touchpad_confirm_connect`，含 `{name}` 占位）
  - 确认按钮：`确认` → 开始触摸控制、进入触摸板页面
  - 取消按钮：`取消` → 仅关闭弹窗，不做任何连接
- 进入触摸板页面后：建立专用 UDP、开始采集 MotionEvent、按设置取背景（OLED/深灰）。

### 11.3 一对一独占控制（占用状态显示为 TODO）

- **约束**：一台桌面设备同一时刻只能被一台安卓设备控制；一台安卓设备同一时刻只能控制一台桌面设备。
- **占用判定**（TODO，当前仅本机状态字段）：点击设备时，若该桌面设备已被其它安卓设备控制（状态来自数据面 TCP 层的占用通告，见下），该设备行显示"被占用"且不可连接（或点击提示"该设备正在被 XXX 控制"）。
- **占用状态同步**：占用/释放通过专用 TCP 通道的点对点状态交换实现（连接握手时双方确认；群主不参与控制面占用仲裁，因为触控板是点对点直连）。具体 wire 字段在实现时定；设计上：
  - 安卓连上某 PC 后，PC 端记录"被本机控制"；本机记录"正在控制该 PC"。
  - 本机已控制一台 PC 时，设备列表其它 PC 不可再连（先退出当前控制才可切换）。
- **释放时机**：安卓**退出触摸板页面即退出控制**——关闭 UDP、PC 端释放占用、本机清空"正在控制"状态；返回后设备列表恢复可连。
- **异常释放**：UDP 断线/心跳失联等价于退出控制，双方各自释放占用（避免"幽灵占用"）。

### 11.4 触摸板设置列表（三个开关）

位置：设备列表下方，触摸板 tab 内。设置**本地持久化**（跨会话保留；实现时接本地存储，与现有共享文件夹清单持久化同机制）。

| 设置项 | key | 开 | 关 | 默认 |
|---|---|---|---|---|
| 震动反馈 | `touchpad_haptics` | 触碰/按键时震动（见 §5） | 不震动 | 开 |
| OLED 模式 | `touchpad_oled` | 触控板页纯黑 `#000000` | 深灰（建议 `#212121`） | 开 |
| 粒子特效 | `touchpad_particles` | 触碰点显示粒子/涟漪（见 §6） | 无特效 | 关 |

- 三个开关改动**立即生效于下次进入触摸板页**（若已在触摸板页内改动，实时应用——实现时决定）。
