## KnotInput + 群 tab 滑动色块
- 用户自建 KnotInput（components/Common.kt）：BasicTextField 自绘 10dp 圆角描边，水平10/垂直8 padding，聚焦切主题色；HomeScreen/GroupTabs 已接入。
- 群 tab 三方式切换（最终版）：GroupTabBar 改为完全独立的悬浮组件，**不再持有 pagerState**（只收 page: Float + onSelect 回调）。tab 栏横滑只累加本地 dragOffset（mutableFloatStateOf，同步无携程）让色块跟手，页面纹丝不动；松手按 visualPos round 算目标 → onSelect 让外部 animateScrollToPage，同时 settle() 用单个可取消 Job + Animatable.snapTo(当前dragOffset).animateTo(0) 把色块偏移平滑归零。
- 闪退根因：旧版 onHorizontalDrag 每事件 launch 一个协程操作 pagerState，高频并发冲击 pager 状态机崩溃；且 dragAmount 是增量非累计，用 startPage+dragAmount 计算错误（应累加）。重构后拖动期零携程碰 pager。
- 版本 API 坑：detectHorizontalDragGestures 回调名 onHorizontalDrag（非 onDrag）；consume() 是成员方法无需 import；Animatable.stop() 是 suspend 不能在 onDragStart 直调（改用 Job.cancel）。
- 剪切板页色块拖不动的 bug：pointerInput(Unit) 闭包只启动一次，捕获了旧 page=0，切到 page=1 后 clamp 仍用 [-0,1-0]，左拖 offset 变负被 clamp 到 0。修复：rememberUpdatedState(page) 闭包内读 pageState.value。教训：pointerInput 闭包捕获的状态要用 rememberUpdatedState 读最新值。
- 输入框点击外部失焦：GroupBody 最外层 Box 加 pointerInput+detectTapGestures(onTap={focusManager.clearFocus()})；点输入框本身它消费 down 事件，父 onTap 不触发不失焦；点空白区清焦点收键盘。LocalFocusManager。
- tab 去 ripple：item 的 clickable 传 interactionSource=remember{MutableInteractionSource()}+indication=null。
- 按下色块立即跟手：onDragStart 用落点 startOffset.x 算 desiredPos=(x-segW/2)/stepPx，dragOffset=desiredPos-pageState.value；松手才 onSelect。

- 11-22 P2P 传输慢的诊断结论（用户决定：性能优化是以后的事，本次不改代码）：
  - 根因不是算力/依赖，是协议：当前"停等式 ACK"（stop-and-wait）——供种端每发 64KiB 就阻塞等下载端一个 ACK（Rust file.rs serve_one/fetch_file、Kotlin P2pFileService serveOne/download 都是）。每块耗时 ≥ 1 RTT，局域网 RTT 1~3ms → 吞吐天花板约 30MB/s 甚至更低，跑不满千兆。次要损耗：每块 vec 分配、idx/len/数据三次 write_all（Nagle）、TCP 窗口填不满。
  - 换依赖无用：只要还是每块等 ACK，换加密库/网络库都救不了。
  - 以后做时的方向（用户拍板）：**彻底改协议为滑动窗口/流水线**（连续发 N 块不等 ACK、接收端批量确认），不追求最小改动；**不需要断点续传**（没有暂停功能），resume_from 可一并去掉；改动两端 file.rs / P2pFileService.kt，需重做进度上报与取消逻辑。
  - 依赖规矩：用户未禁止依赖，但**用依赖前必须先告知具体依赖名称/用途/版本等确认**；本次吞吐优化用现有 tokio 即可，无需新依赖。
