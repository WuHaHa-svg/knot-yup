# 安卓触控板功能设计

> 状态：**设计稿，待实现**。本文是「安卓触控板」功能的唯一设计来源；总纲见 [ARCHITECTURE.md](ARCHITECTURE.md) 的「触控板（M3）」一节。
> 依赖：局域网星型群（[ws-design.md](ws-design.md)）、Android 前台 MotionEvent 采集、桌面端系统级输入注入。

## 1. 定位与已确认决策

把安卓手机当作 PC 的触控板：手机全屏采集触摸，增量事件经**专用 TCP 通道**直送桌面端，注入为系统光标/滚动/点击（Windows `SendInput`、macOS `CGEvent`）。目标是**低延迟、纯黑省电、手势直观、反馈可感**。

已拍板（不可随意推翻）：

| 维度 | 决策 |
|---|---|
| 传输通道 | **独立专用 TCP**（不与群组 ws 混用）：端到端目标 **< 20ms**；ws 只负责发现/连接信息交换 |
| 拓扑 | 手机 = 控制端，PC = 被控端；**点对点直连**，不经群主转发 |
| 坐标语义 | 传**增量 dx/dy**而非绝对坐标；PC 端光标位置由系统维护 |
| 屏幕背景 | 触控板页面**纯黑 `#000000`**（OLED 友好了不发光像素）；不受系统深色/浅色模式影响 |
| 数字键盘 | 半屏浮层，手势开/关、手势切左右；**不抢占触控板手势**（见 §4） |
| 震动 | 接入系统震动反馈，强度/开关可调（见 §5） |
| 粒子特效 | **可选增强**，默认可关，性能优先（见 §6） |
| 生命周期 | 触控板页面仅**前台**工作；离开页面即断开 TCP、停止采集与注入 |

## 2. 整体数据流

```
┌─ Android（控制端）────────────────────────────────┐
│ TouchpadScreen（纯黑全屏）                        │
│   ├─ MotionEvent 采集 → 手势识别 → 增量打包         │
│   ├─ 数字键盘浮层（半屏，左/右）                    │
│   ├─ 震动反馈（按事件触发）                         │
│   └─ 粒子特效（可选，触碰点渲染）                    │
│         │ 专用 TCP（JSON 或二进制帧，见 §3）        │
└─────────┼──────────────────────────────────────────┘
          ▼
┌─ Desktop（被控端，Tauri）──────────────────────────┐
│   TCP 监听 → 解帧 → 事件分发                       │
│     → Windows SendInput / macOS CGEvent 注入        │
└─────────────────────────────────────────────────────┘
```

- **连接建立**：复用局域网发现拿到的 PC `addr`；手机连 PC 的触控板 TCP 端口（固定端口 + 握手令牌，防止误连）。连接参数由群组/发现层提供，但**数据面独立于 ws**。
- **前台约束**：Android 前台 Activity 才能采集 MotionEvent；App 退后台立即断开，避免"手关机了光标还在动"。
- **幂等/乱序**：增量事件是流式，允许极端丢帧（下一段 dx/dy 承接当前位置），但**按键 down/up 必须成对可靠送达**（见 §3 可靠性）。

## 3. 事件协议（专用 TCP）

### 3.1 帧格式

优先**紧凑二进制帧**（1 字节类型 + 载荷）把延迟和包体压到最低；首版可用 JSON 降级实现，字段对齐如下。所有事件带 `seq`（单调递增，接收端用于丢弃乱序旧帧）。

| 事件 | type | 载荷 | 说明 |
|---|---|---|---|
| 握手 | `hello` | `{token, device_id, screen_w, screen_h}` | 连接后首帧；token 校验防误连 |
| 移动 | `move` | `{seq, dx, dy}` | 相对位移，浮点或定点整数；高频 |
| 滚动 | `scroll` | `{seq, dx, dy}` | 双指滚动增量（与移动分离） |
| 按键按下 | `down` | `{seq, button}` | button: left/right/middle |
| 按键抬起 | `up` | `{seq, button}` | 与 down 成对 |
| 点击 | `click` | `{seq, button}` | 点按（down+up 合成，PC 端一次注入） |
| 双击 | `dblclick` | `{seq, button}` | 双击拖拽起手 |
| 拖拽 | `drag` | `{seq, btn, phase}` | phase: start/move/end |
| 按键输入 | `key` | `{seq, code}` | 数字键盘的按键（见 §4.3） |
| 心跳 | `ping/pong` | `{ts_ms}` | 保活 + 延迟测量 |

### 3.2 可靠性

- **move/scroll**：允许丢帧（UDP 式语义，TCP 上也不重传旧帧，接收端按 seq 丢弃过期包），保证光标跟手、不积压。
- **down/up/key**：可靠送达（不经丢弃逻辑），且 PC 端做**松开兜底**：连接断开或超时未收到 up 时，注入一次全局抬起，防止"按键卡住"。
- **背压**：发送队列超过阈值（如 64 帧）丢弃最旧的 move/scroll，只保留最新位置增量。

## 4. 数字键盘（显示/隐藏 + 左右切换）

### 4.1 形态

- 触控板页面上方覆盖一个**半屏浮层**（占屏幕高度的 1/2 或宽度的一半，见 4.2），承载数字键盘：0-9、小数点、退格、加减乘除、回车（布局待细化）。
- 浮层背景保持**纯黑**，按键为深色描边 + 主色高亮（与全局主题一致），不破坏 OLED 省电目标。
- 键盘按键点击 → 发 `key` 事件注入 PC；按键触发点按震动（见 §5）。

### 4.2 手势定义（关键：不与触控板手势冲突）

约定一条**统一的唤出/切换手势**，并明确它与普通触控操作的边界：

| 手势 | 动作 | 效果 |
|---|---|---|
| 唤出数字键盘 | 屏幕**底部边缘上滑**（短距、快速） | 显示半屏数字键盘（默认右半屏） |
| 隐藏数字键盘 | 数字键盘浮层上**下滑**，或再次底部上滑 | 隐藏浮层，回到全屏触控板 |
| 切换位置 | 在数字键盘浮层上**左右横滑** | 浮层在**左半屏 ⇄ 右半屏**间切换 |

冲突规避：
- 唤出手势限定在**底部安全区**（如底部 24dp 条带）内才生效；该区域内不做普通光标移动，避免误触。
- 数字键盘显示时，**触控板采集区收窄为浮层以外的半屏**——此时单指移动/双指滚动仍可用，但作用于剩余半屏，手感一致。
- 手势识别用**阈值 + 方向 + 时长**三重判定（滑动距离 > 64dp、主方向明确、时长 < 300ms），与拖拽/滚动区分。

### 4.3 键盘输入语义

- 数字键盘的每次按键 → `key{code}` 事件 → PC 端注入对应键码（0-9: `VK_0`~`VK_9` / `CGKeyCode`，符号类似）。
- 输入目标是 PC 当前焦点窗口（与触控板注入目标一致），不做手机端文本框。
- 位置状态（左/右）与显示状态（显示/隐藏）都是**本地 UI 状态**，不跨设备同步、不持久化（退出触控板页重置为隐藏）。

## 5. 震动反馈（"震动调教"）

接入 Android `Vibrator`（`VibratorManager` API 31+，兼容 `Vibrator`）做事件驱动反馈，并提供**可调设置**：

| 事件 | 震动 | 说明 |
|---|---|---|
| 点按 `click` | 短促轻震（如 15ms） | 确认落点 |
| 双击/拖拽起手 | 双震或略强（如 20ms×2） | 区分单击 |
| 数字键盘按键 | 极短轻震（如 10ms） | 打字感 |
| 唤出/切换键盘 | 中等一震（如 30ms） | 手势确认 |
| 连接/断连 | 特定节奏（连接短两下、断连长一下） | 状态提示 |

可调项（"调教"）：
- **总开关**：默认开；用户可全局关闭。
- **强度档位**：轻/中/强（映射到 duration 或 amplitude），设置页/触控板页内可切换。
- **逐事件开关**（可选）：允许单独关闭"移动震动"等高频反馈，避免连续震动手麻。
- 震动仅在**前台触控板页**触发；退后台不震。
- 无震动硬件的设备静默降级（检测 `hasVibrator()`），不影响功能。

## 6. 粒子特效（可选增强）

触碰时在触点渲染短暂粒子/涟漪，提升反馈感。**明确为可选、性能优先**：

- **开关**：默认**关**（保证低端机与省电）；设置里可开。
- **实现**：Compose `Canvas`，每次 `ACTION_DOWN`/移动采样点生成一组短生命周期粒子（位置、速度、透明度衰减），`withFrameNanos` 驱动，粒子数上限（如 40）+ 生命周期（如 400ms）后回收。
- **OLED 友好**：粒子用**亮色小点**（白/主色）绘制在纯黑底上——仅点亮局部像素，符合省电目标；不用大面积渐变。
- **降级**：帧率低于阈值或开关关闭时不渲染；粒子特效**不影响事件采集与注入**（渲染与采集解耦，掉帧只丢视觉，不丢控制）。
- 与数字键盘共存：浮层区域内也可渲染，但按键高亮优先。

## 7. 桌面端注入

- **Windows**：`SendInput` 注入相对移动（`MOUSEEVENTF_MOVE`）、滚轮（`MOUSEEVENTF_WHEEL`）、按键（`MOUSEEVENTF_LEFTDOWN/UP` 等）、键码（`keybd_event`/SendInput KEYBD）。
- **macOS**：`CGEvent` 对应 `CGEventCreateMouseEvent`（move/leftDown/leftUp/otherMouse）、`CGEventCreateScrollWheelEvent`、`CGEventCreateKeyboardEvent`。
- **权限**：macOS 需辅助功能/输入监控授权（首次引导）；Windows 一般免授权。
- 注入在**独立线程**执行，与 Tauri 主 UI 解耦；接收循环按 `seq` 过滤 + 松开兜底（见 §3.2）。

## 9. 分期计划

| 阶段 | 范围 | 产出 |
|---|---|---|
| **T1 通路 + 基础触控** | 专用 TCP、握手、hello/move/click/scroll 最小集、桌面注入（先单平台）、纯黑页面 | 手机能当基础触控板用，延迟达标 |
| **T2 手势完善** | down/up/双击/拖拽、ping/pong 延迟、按键松开兜底、双平台注入 | 手势完整、不断键、双端可用 |
| **T3 数字键盘** | 半屏浮层、底部上滑唤出/隐藏、横滑切左右、`key` 注入 | §4 全部功能 |
| **T4 震动调教** | Haptics 封装、设置项、逐事件反馈 | §5 全部功能 |
| **T5 粒子特效（可选）** | Canvas 粒子、开关、性能降级 | §6，可裁剪 |

## 10. 风险与待定

- **延迟**：TCP + JSON 首版可能达不到 <20ms；用二进制帧 + 高频事件丢弃 + 直连保障，必要时调 Nagle（TCP_NODELAY）。
- **手势冲突**：底部唤出手势与"从底部开始的移动/拖拽"冲突——靠限定底部安全区 + 阈值判定；实机调参。
- **系统注入权限**：macOS 辅助功能授权是硬性前置，需在引导页说明；无授权时功能不可用并给出提示。
- **震动舒适度**：连续移动震动易手麻——默认只对离散事件（点按/按键/手势）震，不跟随移动；强度可调。
- **粒子性能**：低端机 Canvas 粒子掉帧——默认关、上限粒子数、渲染与采集解耦。
- **touchpad 入口位置**：放在首页还是群页、是否需要"选中某台 PC"再连——待产品确认（本文按"从发现到的 PC 直连"设计）。
- **多 PC / 多手机**：首版一对一；一对多连接选路由后续扩展。
